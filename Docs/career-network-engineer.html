Career Deep Dive · 03 · The Jobs

Network Engineer

Route data packets across a shifting grid of tiles to their destination — our deepest, most fully-realized career.

● FEATURED — most complete Scene: GameDev.unity Photon-networked Teaches: packets, routing & timing

How it was made

The networking job is built from six focused scripts in Assets/_Scripts/GamingMap/, layered on Unity physics and Photon PUN 2.

The core scripts

  • Packet.cs — the data packet itself. Inherits MonoBehaviourPun and implements IPunObservable, so its isDelivered state is serialized over the network and every client agrees on which packets have arrived.
  • IPdraggable.cs — the first-person pick-up / carry / throw mechanic. A forward Physics.Raycast (5-unit range) finds objects by tag; the held packet is parented to a holdPos transform and made kinematic so physics won't fight the player.
  • PacketGoal.cs — the delivery zone. OnCollisionEnter detects an arriving packet and calls ScoreManager.Instance.AddScore(10).
  • Tiles.cs — the living floor. A StartCoroutine(TilesFaded()) loop cycles each tile white → yellow (1s warning) → red (collider disabled, impassable) on a random 3–10s interval.
  • FadeTiles.cs — discovers all child tiles and manages them as a group.
  • Clickable.cs — a raycast utility for toggling objects (currently mostly dormant/commented).

Unity techniques in play

  • Material emission, not shaders — packets glow cyan on spawn and flip to green on delivery by setting _EmissionColor and enabling the _EMISSION keyword on the Standard material. Cheap and readable.
  • Kinematic + collision-ignore carry — while held, the packet ignores collisions with the player to stop clipping, and rides on a dedicated holdLayer.
  • Coroutine-driven hazards — the fading tiles are pure coroutine timing, giving a platforming challenge without any animation assets.
  • Networked state — OnPhotonSerializeView transmits delivery status so a packet delivered on one machine reads as delivered everywhere.
Honest engineering notes

Delivery is one-directional: once isDelivered is set, the packet's tag flips to Untagged so it can't be grabbed again. There's no round/timer logic inside these scripts — game-end lives elsewhere. Clickable.cs carries three obsolete commented-out versions, and rotation sensitivity is hardcoded to 1f rather than exposed in the Inspector.

How it's played

A delivery loop set on a floor that won't stay put.

Spot a packet

Cyan-glowing packets are scattered around the level. Look at one within 5 units and click — a raycast picks it up and it parents to your hands.

Carry, rotate, or throw

Left-click to drop, right-click to throw with force, hold R + move the mouse to rotate the packet in place.

Cross the live grid

The floor tiles cycle passable→warning→impassable every 3–10 seconds. Time your route across tiles before they drop out.

Deliver to the goal

Land the packet in the goal zone. It turns green, scores +10, and goes Untagged so it can't be re-delivered.

Synced for everyone

Packet delivery state syncs over Photon, so every player in the room sees the same deliveries happen live.

What it teaches

  • Packets — data travels in discrete pieces, carried one at a time.
  • Routing — finding a viable path to the destination.
  • Timing & latency — the network (the tile grid) changes moment to moment.
  • Synchronization — keeping every node in agreement on state.

How it could be improved

Concrete next steps, grouped by what they'd buy us.

Bugs & correctness

  • Concurrent-delivery double score — if two clients see the same packet enter the goal, OnCollisionEnter fires on both. Gate scoring behind a Photon RPC owned by the master client.
  • Coroutine never stops — TilesFaded()'s while(true) loop has no OnDestroy teardown; stop it when the tile is destroyed.
  • Per-frame RaycastAll — anti-clip checks run every Update while carrying. Debounce to drop/throw moments only.

Gameplay depth

  • Difficulty scaling: faster tile cycles and shifting patterns as score climbs.
  • Packet variety: heavy vs. light packets to model data size & congestion.
  • Near-miss feedback: particles/sound when a packet lands just short of the goal.
  • Packet loss events: randomly drop an in-flight packet with a "Packet Lost" notice.

Educational value

  • HUD tooltips that name the metaphor: "Tiles = network nodes; red = offline/congested," "Goal = destination server."
  • A pre-game briefing and a post-game performance review (delivered / on-time / lost).
  • An optional modal on OSI layers and TCP vs. UDP for judges who want the depth.

Code health

  • Delete the dead Clickable.cs variants; keep one.
  • Serialize rotationSensitivity so designers can tune it.
  • Add photonView.IsMine ownership checks so players grab only their own/unowned packets.
